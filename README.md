# Rolelab

Совместная оценка бизнес-критичности ролей: ведущий управляет встречей, участники с телефонов отправляют шесть оценок, в конце появляется рейтинг ролей.

## Размещение

Интерфейс размещается на GitHub Pages, данные и проверка прав работают в Supabase PostgreSQL. Для рабочей встречи локальный компьютер или Node.js-сервер не нужен.

- [Сайт](https://training-academy-airastana.github.io/rolelab/)
- [Репозиторий](https://github.com/training-academy-airastana/rolelab)
- [Проект Supabase](https://supabase.com/dashboard/project/baweqpeeurmwvcqwtcom)

## Провести встречу

1. На главной странице ввести имя `admin1`, чтобы открыть интерфейс администратора. Нажать «Начать встречу», ввести название и список ролей, по одной на строку.
2. Отправить участникам общий адрес сайта. Они вводят имя и автоматически подключаются к текущей встрече. Код и отдельная ссылка для каждой встречи не нужны.
   Кнопка «QR-код» открывает крупный код для экрана в переговорной. «На весь экран» скрывает интерфейс браузера; «Скопировать ссылку» позволяет отправить этот же адрес участникам с компьютера. После сканирования участник вводит имя. QR-код генерируется в браузере и не требует стороннего сервиса.
3. Открыть «Общий экран» для проектора. Выбрать роль и открыть голосование.
4. Участники ставят все шесть оценок от 1 до 5 и отправляют один ответ. После отправки ожидают остальных.
5. Закрыть голосование, обсудить результат и выбрать следующую роль. Завершить сессию, чтобы показать общий рейтинг.

При входе сайт спрашивает имя и запоминает его до закрытия вкладки. Кнопка «Сменить имя» возвращает форму входа. Любое имя, кроме точного `admin1`, подключает к текущей встрече. Если ведущий ещё не создал встречу, участник ждёт и подключается автоматически, когда она появится. Новая встреча становится текущей для всех; после завершения участники сохраняют доступ к её результатам до начала следующей встречи. Повторные запросы и обновление страницы восстанавливают того же участника. Старые ссылки-приглашения продолжают работать для указанной в них встречи.

Имя `admin1` выбирает интерфейс ведущего. Управление конкретной встречей по-прежнему требует её ключ, выданный при создании; ввод имени не выдаёт доступ к чужой сессии.

Ключ ведущего хранится в браузере, в котором создана встреча. Не очищать данные этого браузера во время сессии. Автоматический вход выдаёт только личный доступ участника. Пользователь видит имена участников, статус ответов и общую статистику, но не персональные оценки. Пределы одной сессии: 100 ролей и 200 участников.

В демонстрационном режиме используются явно отмеченные примеры. Его данные сохраняются только в текущем браузере; кнопка «Сбросить демо» начинает демонстрацию заново.

## Расчёт

Веса критериев: 25%, 25%, 20%, 15%, 10%, 5%. По каждому критерию вычисляется среднее всех полных ответов, затем средние умножаются на веса и складываются. Итог находится в диапазоне 1–5. Сортировка выполняется по полной точности, отображение с двумя знаками после запятой. При одинаковом результате роли делят место. Роли без ответов не участвуют в рейтинге.

Результаты до закрытия раунда не передаются в браузер. Единственный ответ участника на роль закреплён уникальным ограничением базы. Закрытие раунда и отправка ответа используют одну блокировку, исключающую попадание позднего ответа в закрытое голосование. Обновление экрана выполняется каждые 1,5 секунды, пока вкладка открыта.

## Разработка и публикация

Требуется Node.js 24.

```sh
npm ci
npm test
npm run build
npm start
```

Локальная страница: http://localhost:4173. Если [конфигурация Supabase](./public/config.mjs) заполнена, локальный интерфейс тоже использует облачную базу. При пустой конфигурации доступна автономная демонстрация и вспомогательный локальный сервер.

[Основная миграция](./supabase/migrations/202611240001_rolelab.sql) применяется один раз к новому проекту через SQL Editor или Supabase CLI. Затем применяется [автоматический вход в текущую встречу](./supabase/migrations/202611240002_current_meeting.sql). Для существующего проекта достаточно второй миграции. После её установки ведущий создаёт новую встречу; старые встречи не становятся текущими автоматически. Таблицы находятся в закрытой схеме с включённым RLS; браузеру доступны только функции с проверкой ключей доступа. Отсутствие текущей встречи возвращается без раскрытия списка предыдущих встреч.

[GitHub Actions](./.github/workflows/pages.yml) проверяет проект и публикует содержимое `dist` при изменении ветки `main`. В настройках GitHub Pages источник публикации: **GitHub Actions**. Необязательные repository variables `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY` переопределяют публичную конфигурацию при сборке. Сборка публикации останавливается, если Supabase не настроен.

В клиентской конфигурации используется только публичный `sb_publishable_…` ключ. Он может находиться в исходном коде. Секретные ключи и `service_role` для этой архитектуры не нужны; сборка их отклоняет. Подробнее: [API keys](https://supabase.com/docs/guides/getting-started/api-keys), [Database functions](https://supabase.com/docs/guides/database/functions), [GitHub Pages workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

`npm test` включает проверки SQL-схемы в PostgreSQL WebAssembly, прав доступа, скрытия результатов, дублей, расчёта среднего и ссылок с префиксом репозитория. `node test/cloud-smoke.mjs` проверяет подключённый облачный проект на синтетической сессии и завершает её после проверки.
